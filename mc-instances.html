实现要求

          

            

              
1. 实例上传

              
    
                
  • 范围：只提交最小可复现集；libraries/ assets/ versions/ logs/ 默认排除，由启动器重建。
    • 
                
  • 去重：每个文件算 git blob SHA（SHA-1），与仓库现有同名路径比对，一致则零请求跳过。
    • 
                
  • 分块：单文件 > 16MB 切成 parts/xxx.partNNN，规避 Git Blob API 100MB 上限。
    • 
                
  • 提交：一次上传用一个 tree + 一个 commit 完成；删除项写 sha:null 才会真删。
    • 
                
  • 并发与重试：顺序上传避免限流；失败按指数退避重试 2 次。
    • 
              

            

            

              
2. 版本识别

              
    
                
  1. mmc-pack.json（Prism / MultiMC 的 components）
    2. 
                
  2. versions/*/*.json：id / inheritsFrom / libraries 里的 net.minecraftforge:forge:1.20.1-47.2.20 等坐标
    3. 
                
  3. logs/latest.log 首行：Loading Minecraft X with Forge Y
    4. 
                
  4. 以上都失败 → 要求手填，并按「MC 版本 + 加载器 + 模组指纹」生成 fingerprint
    5. 
              

              
指纹用于判断“版本没变但内容变了”，并在同步时快速确认是否需要更新。

            

            

              
3. 下载缓存

              
    
                
  • 以内容哈希为键存 Cache Storage，同一文件跨实例、跨次同步复用。
    • 
                
  • 分块文件按块缓存：中断重试只补缺块，已下载块不重传。
    • 
                
  • 命中缓存直接写盘，跳过网络；缓存命中率与占用可在页面查看/清理。
    • 
                
  • 写盘后按清单 sha256 校验，不一致则淘汰该缓存条目并重试一次。
    • 
              

            

            

              
4. 更新冲突

              
    
                
  • 三方比较：本地 / 基线 / 云端，分为「仅云端改」「仅本地改」「两边都改」「单边新增/删除」。
    • 
                
  • 两边都改 = 冲突，逐文件选择「用云端 / 保留本地 / 两者都留（改名 .local-时间戳）」。
    • 
                
  • 世界存档默认保护：saves/ 下冲突默认保留本地，避免覆盖进度。
    • 
                
  • 提交时使用 force:false；分支被他人推进则重新比对后重试，最多 2 轮。
    • 
              

            

            

              
5. 错误处理

              
    
                
  • 错误分类：E_AUTH / E_SCOPE / E_RATELIMIT / E_NET / E_TIMEOUT / E_TOO_LARGE / E_CONFLICT / E_FS_DENIED / E_FS_LOCKED / E_HASH / E_SCHEMA。
    • 
                
  • 每类错误给出中文原因与下一步动作，日志保留原始响应供排查。
    • 
                
  • 限流读取 X-RateLimit-Reset 自动等待；网络错误指数退避；非幂等操作不自动重试。
    • 
                
  • 文件被占用（游戏运行中）单独识别，提示先退出游戏，不强行覆盖。
    • 
              

            

            

              
6. 启动方式（边界）

              
    
                
  • 浏览器只能写文件、生成脚本，不能直接运行 exe。
    • 
                
  • 同步完成后写入 niao-launch.cmd 与 launch-plan.json，双击即用启动器打开实例。
    • 
                
  • 可选注册 niao-mc:// 协议，让页面按钮唤起本地脚本（需运行一次 .reg）。
    • 
                
  • 启动参数（内存 / JVM）随实例清单下发，游戏仍按本地启动器规则运行。
